# Портфельный набор данных

Расширение демо-набора до шести объектов. Нужно для первого экрана: на одном
объекте портфельная лента выглядит пустой и идея не читается.

Дата среза та же — **5 сентября 2026**.

| Файл | Что внутри |
|---|---|
| `objects.csv` | шесть объектов на разных стадиях, с триадой процентов и числом расхождений |
| `alerts.csv` | пять расхождений по всем объектам, с состоянием обработки |
| `contacts.csv` | ответственные: подрядчик на объекте → человек, телефон, мессенджер, эскалация |

Детальный объект остаётся один — `OBJ-01`, ЖК «Северный», корпус 2. Все четыре
заложенные ситуации живут в нём (`../plan.csv`, `../detections.json`).
Пять остальных объектов фоновые: у них заполнена только сводка, детализация
не нужна ни для показа, ни для тестов.

## Триада процентов

Три числа, вокруг которых собран первый экран.

| Поле | Как считается |
|---|---|
| `plan_today_pct` | доля пройденных **рабочих** дней от плановой длительности работы |
| `reported_pct` | колонка факта в графике — то, что заявил подрядчик |
| `confirmed_days` / `elapsed_days` | дней с уровнем подтверждения ≥ 2 из прошедших рабочих дней |

`confirmed_days / elapsed_days` **не является измерением объёма**. Объём система
не меряет — это уровень 3 лестницы, он вне MVP. В интерфейсе третье число всегда
подписано «подтверждено наблюдением» и всегда сопровождается дробью в днях.

На уровне объекта три числа взвешены по плановой длительности работ в рабочих
днях. Других весов в данных нет: трудоёмкости в графике подрядчик не указывает.

## Обработка расхождения

`handling` принимает четыре значения: `new` → `seen` → `in_work` → `closed`.
Закрытие требует исхода: подтвердилось, объяснено подрядчиком либо ложное
срабатывание. Последний исход — обратная связь на модель.

`untouched_days` — сколько суток расхождение висит без единого просмотра.
Это метрика бездействия, она видна на карточке.

## Ответственные

`contacts.csv` отвечает на вопрос, которого нет в календарном плане: **кому звонить**.
В графике есть только `contractor` — название организации. Ключ справочника
составной, `contractor + object_id`: один подрядчик на разных объектах ведёт
разными людьми.

Взятие расхождения в работу — это не отметка, а обращение к конкретному
человеку. Система показывает контакт и собирает текст запроса из фактов
расхождения, пользователь выбирает канал.

У подрядчика `ГеоСтрой` контакт **намеренно не заполнен**. Карточка в этом
случае честно говорит «обратиться не к кому, заполните контакт в настройке».
Единственное состояние, в котором система не может предложить действие, и
прятать его нельзя.

Правило эскалации: нет ответа двое суток — второй контакт из тех же строк.
