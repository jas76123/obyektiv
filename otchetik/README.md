# «Отчётик»: приложение прораба

Мобильное приложение к «Объективу»: прораб снимает результат работы одной кнопкой, фото
сохраняется на телефоне и досылается на сервер, когда есть сеть; статусы, факт и рейтинг
бригад приходят с сервера. По документу `construction-monitoring/docs/FOREMAN_APP.md` (бизнес-логика приложения прораба).

## Как открыть

- Android: APK — ссылка появится здесь после сборки в EAS (`npm run build:apk`). При
  установке разрешить установку из файла. Приложение ходит на сервер команды по http напрямую.
- iPhone и любой браузер: `https://<id>.apigw.yandexcloud.net/obyektiv/` (адрес появится
  после выкладки, см. `deploy/README.md`). Страница и сервер на одном адресе, поэтому
  камера и координаты работают.
- Демо без сервера: https://jas76123.github.io/obyektiv/ (GitHub Pages, только https, до
  сервера по http не достаёт; в России открывается с перебоями).

## Разработка

    npm install
    npx expo start          # Expo Go на телефоне или w для браузера
    npm test                # Vitest: контракт, статусы, источник, очередь, отправщик, лента
    npm run typecheck
    npm run build:apk       # EAS Build, профиль preview (APK)
    npm run deploy          # веб-версия в ветку gh-pages
    npm run deploy:web      # веб-версия в бакет Yandex Object Storage (см. deploy/README.md)
    npm run deploy:gw       # обновить шлюз из deploy/apigw.yaml

## Стыковка с сервером

Контракт: `contract/README.md`, примеры ответов `demo/*.json`. Адрес сервера по умолчанию:
в сборке на телефоне — `http://217.18.63.89:8000`, в вебе на шлюзе — свой же адрес, в
остальных случаях (GitHub Pages, локальная раздача) — пусто, то есть демо. Скрытая
настройка (долгое нажатие на номер версии на экране входа) перекрывает умолчание;
переключатель «Только демо-данные» = работа на вшитых данных с пометкой «демо».

Статус работы на экранах — одно из трёх слов: «не начато» (фото нет), «в работе»
(фото есть), «переснять» (нейросеть на последнем фото ничего не нашла или сервер
вернул фото). Результат нейросети приложение спрашивает у `GET /photos` один раз на
прогон очереди, не чаще раза в минуту; выключатель «Проверять фото нейросетью» в
скрытых настройках (долгое нажатие на версию на экране входа). Слова «ждёт сети»,
«отправляется», «отправлено» — про доставку фото, не про работу; без адреса сервера
очередь подписана «ждёт сервера».

Рейтинг бригад при живом сервере считается на телефоне из `GET /photos`: бригада и наряд
едут в имени файла при загрузке (`br-1.t-doors-0922.<uuid>.jpg`); принято = фото с
непустыми детекциями, качество = их доля в процентах, баллы = принято × 10 (формула из
документа §11 без вердиктов и оценки качества, которых в цепочке нет). Серверный
`/api/foreman/leaderboard` используется только в демо.

## Ограничения

- Досылка в фоне на Android: не раньше чем через 15 минут и когда система решит; после
  принудительного закрытия приложения до следующего запуска. Основная досылка: при съёмке,
  при появлении сети, при открытии приложения.
- В браузере фоновой досылки нет, хранилище небольшое (порядка 10–15 фото).
- iOS-сборки нет (нужен платный аккаунт Apple); на iPhone работает веб-версия. Когда сборка
  появится, серверу по `http://` понадобится исключение ATS в `app.json`
  (`ios.infoPlist.NSAppTransportSecurity`) — иначе приложение молча не увидит сервер.
- Веб-версия на https (GitHub Pages) ходит только на https-сервер: смешанный контент
  браузер не пустит, а на http-странице нет геолокации. Поэтому веб раздаётся через
  шлюз в Yandex Cloud (`deploy/`), где страница и сервер на одном адресе. Иностранные
  прокси (Cloudflare) в России режутся, GitHub открывается с перебоями.
- Сервер команды однопоточный: пока считается чужой `/photos` (~20 с), остальные запросы
  ждут; таймауты приложения 25 с на чтение и 45 с на отправку.
